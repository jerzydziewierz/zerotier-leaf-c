# Contract changes and tightenings applied to the C leaf

Strand `ztram`, repository ``. One paragraph per change, written as raw material for a blog post. Each entry says: what the contract or check said before, which wrong program it would have accepted, how the weakness was found, what changed, and the evidence after the change. "Contract" means the written statement that a prover checks the code against (ACSL for Frama-C WP), and also the rules of the proof runner, because a weak runner accepts wrong programs too. IDs are stable; new entries go at the end. Proof numbers are those of the run named in `reports/PROOFS.md`.

How the weaknesses were found, in order of yield: (1) writing the real code behind an interface that was only a contract before; (2) two independent read-only reviews of code, contracts and runner; (3) turning on stricter prover options; (4) deliberate errors ("mutants") that no tool rejected.

## 2026-11-13

**IA-1. The packet ID is now inside the deductive contract.** Before: the classifier's WP contract fixed every output field except the 64-bit packet ID; its value was left to the bounded model checker, because the code built it with shifts in a loop and the automatic provers time out on shift reasoning. Accepted wrong program: one that returns the bytes in another order, as far as WP was concerned. Change: the ID is computed as plain arithmetic (`16777216 * p[0] + 65536 * p[1] + ...`, then high half times 2^32 plus low half), and the contract states the value with the same expression. The compiler emits the same loads. Evidence: WP proves it for every input; two mutants (halves swapped, bytes reversed) are rejected.

**IA-2. "No arithmetic wraps" became a rule that the prover enforces.** Before: C defines unsigned overflow as wrap-around, so the provers did not report it, and two places wrapped on purpose under a `#pragma` that switched one check off. Accepted wrong program: any sum or product that silently loses its top bits, which is the classic error in hand-written multi-word arithmetic. Change: WP now runs with `-warn-unsigned-overflow -warn-unsigned-downcast` on every unit, so each `+`, `*` and narrowing conversion needs a proof that it stays in range. Where the algorithm wants a result modulo 2^32, the code says so (`((uint64_t)a + b) % 4294967296`); the compiler still emits one `add`. Rotations are written as arithmetic too (low bits times 2^c plus high bits) and compile to one `ror`. No `#pragma` is left in `src/`. Evidence: 1,795 goals in 7 units, all proved; target assembly inspected.

**IA-3. The clock difference has an exact contract.** Before: `age_ms()` was `now - then` with the overflow check disabled and the contract "assigns nothing". Change: `(2^32 + now - then) % 2^32` in 64-bit arithmetic, and the contract states that value. This is what made IA-4 possible. A mutant that drops the wrap (`now >= then ? now - then : 0`) is rejected.

**IA-4. The slot choice of the reassembly states its whole rule.** Before: the contract of `ztl_slot_for()` promised only "the result slot waits for this packet or is free; only `have` fields change, only to 0". Timeout and "replace the oldest" were code without a contract, checked only by CBMC at a reduced packet size. Accepted wrong programs: never expire anything; expire a part one millisecond early; replace the newest waiting packet instead of the oldest; free every slot on every call. Change: a predicate "slot i is live at time now" and two behaviours. *match*: a live slot with this ID exists, the result is the first one, no live slot is freed. *no match*: the result is free; if any slot was free or too old then no live slot is freed; if all were live then the result has the greatest age and is the only slot freed. Evidence: 293 goals for the unit at the first complete run; four new mutants rejected. A review then found that the comment claimed more than the contract ("its slot is free" although the scan stops at a match); the comment was narrowed, not the code.

**IA-5. A free slot's time stamp is no longer read.** Found by review: `ztl_reasm_init()` writes only the `have` flags, but the scan computed the age of every slot before looking at the flag. WP could not see this, because its memory model gives an unwritten integer some value; it has no notion of "not initialized". Change: the age is computed only for slots in use, as the data structure's comment always said. Lesson for the post: a deductive proof of "no run-time error" does not cover reads of uninitialized memory unless a tool with that notion (Eva, a sanitizer) runs on the same path.

**IA-6. The authentication primitive is code now, and it meets the contract that the gate assumed.** Before: the gate proof ("nothing is delivered without authentication") used a declaration with a contract: "an answer 0 changes nothing; an answer 1 may rewrite the encrypted part". Nothing showed that an implementation can meet it. Change: `ztl_auth_open()` exists (key mixing, Salsa20/12, Poly1305, 8-byte compare, wipe) and WP proves that contract for it, at the full packet size. Mutant "decrypt although the MAC is wrong" is rejected by WP and by the test vectors.

**IA-7. The proof-only call counter counts per call.** Found while proving IA-6: the gate contract compared a ghost counter with its value at entry, and the implementation's ghost increment needed "counter below the maximum" to be free of overflow, which no long-running caller could ever prove. Change: `ztl_rx()` sets the counter to 0 at entry and its contract says "at most 1 at exit; delivery needs exactly 1 with answer yes". A reviewer objected that a reset could hide an extra call if somebody added a second reset. That is true of any ghost code: annotations are part of the trusted text and must be read. The gate has one ghost line.

**IA-8. The mode of the primitive must agree with the packet.** Found by both reviews: `ztl_auth_open(key, pkt, len, decrypt)` took the mode as a free argument. Accepted misuse: open an unencrypted HELLO with `decrypt = 1` (the function would then XOR plain text), or an encrypted packet with `decrypt = 0`. The gate never did that, but the contract allowed it, and the reference derives the mode from the packet's flags. Change: preconditions "mode is 0 or 1", "mode 1 exactly when the suite bit is set", "no higher suite bit set". To prove these at the call, the gate now applies the classifier's suite rule to the complete packet again, as it already did with the address rule; it no longer relies on what an earlier call left in the reassembly memory. Evidence: gate 192 goals.

**IA-9. The gate theorem names the packet, not only the key.** Found by review: the ghost record of the primitive call held the key and the answer. Accepted wrong program: authenticate one buffer, deliver another. Change: the record also holds the packet pointer and length, and the gate contract states that the delivered body is the rest of exactly that packet.

**IA-10. Poly1305: no limb can overflow, for a message of any length.** New statement. The proof is an invariant on the five 26-bit limbs (limb 1 may exceed 26 bits by a stated amount) that each block step keeps, with every sum and product shown to fit its type. Three tools agree: WP (all lengths, seconds), CBMC as an induction step from any limb values inside the limits (0 of 1,660 checks failed), and a computer algebra system for the true worst case (sums reach 2^58.4 of 64 bits; limb 1 exceeds 26 bits by at most 101, where the invariant allows 4,096).

**IA-11. Poly1305: the steps are proved against arithmetic, with the witness in the contract.** New statements: sixteen bytes and their five limbs stand for the same number; the block step gives exactly `h * r - (2^130 - 5) * k`; the last step gives tag bytes equal to `((h mod 2^130 - 5) mod 2^128 + pad) mod 2^128`. The first attempt stated the block step as "congruent modulo 2^130 - 5" and failed in an unstable way: the same goal passed in one run and timed out in the next. Cause: to prove a congruence, an automatic prover must find the multiplier, and they are poor at finding things. Change: the contract names the multiplier (the part of the product at 2^130 and above, plus the last carry, which is a proof-only output of the function). The goal is then an equality of polynomials. Two more changes of the same kind: the limb value is a macro, not a logic function, so the prover gets the sum itself; and the block step is two functions (add, multiply), because one function with two jobs needed a substitution inside a product. The polynomial identity is confirmed independently by computer algebra.

**IA-12. Wipes survive the compiler, or the build fails.** Found by the target build, not by a prover: the compiler replaced the wipe loop and a zero initializer with calls to `memset` (the runner refuses any C library call), and it may delete writes to an object that is not read again. Change: an empty assembly statement after each write tells the compiler that memory may be read. A review found that the fallback for other compilers was a silent no-op; it is now a build error. The provers see plain C, so this property is checked by reading the compiled code, and the report says so.

**IA-13. "Rejected" in the mutation step now needs evidence.** Found by review: the runner counted a deliberate error as rejected whenever the tool run failed, so a mutant that broke the build or the annotations looked like a proof success. Change: rejected only if a tool ran and reported the error (an unproved goal, a failed check, a failed vector, a sanitizer report); anything else is BROKEN and fails the step. The step also proves only the changed unit, which is sound because each unit is proved alone.

**IA-14. Test vectors come from the reference, and three holes in them were closed.** New check: the real `Packet::armor()`, `Poly1305::compute()` and `Salsa20::crypt12()` of the reference produce the vectors; the leaf must seal to the same bytes, open them, and refuse every one-bit change outside the hop count. Holes: (a) random inputs almost never give a Poly1305 sum at or above the modulus before the last reduction, so vectors were built by hand for exactly that case; a mutant without the final reduction passes all random vectors and fails these. (b) A reviewer showed that "use only the low byte of the block number" passes, because packets need at most 33 blocks; vectors for blocks 255 to 1025 were added. (c) A reviewer showed that "skip block 126" passes, because the longest message had 126 full blocks; messages up to 2,048 bytes were added.

**IA-15. One check was loosened, on purpose.** Eva (abstract interpretation) cannot decide the new value postcondition of the packet ID on unknown bytes and reports "status unknown". The runner now ignores exactly that message kind for Eva; WP proves those postconditions. An "invalid" status still fails. Eva's job here is run-time errors and preconditions.

**IA-16. Two claims were narrowed to what is shown.** The comment of the compare function said "run time does not depend on the contents"; the contract cannot express that, and a compare with an early exit would pass every proof and every vector. The comment now says how the code is written and that the compiled code was read (no branch on a secret byte; the final Poly1305 selection is a multiplication by 0 or 1). The wipe covers the named arrays only; scalar copies in registers and stack slots are outside it.

**IA-17. Result files of two runs cannot mix any more.** Found by review, as an over-claim: a second copy of the runner (used to try one unit while a long run was going) copied its result files into the same local folder, and the reviewer read a stale failure there as the state of the tree. No proof was wrong, but a report that cites result files must be able to say which run wrote them. Change: a tagged copy fetches into its own folder.

**IA-18. A memory error found by the sanitizer counts as "rejected".** The mutation step calls a deliberate error "rejected" only when a tool ran and reported it; every other failure is "BROKEN". For the new protocol test, two errors (a certificate length that is not checked, an ECHO answer longer than the packet buffer) were caught by the address sanitizer, which stops the program with a line that starts "ERROR:" in capitals. The runner's summary line collected lines with "rror" and so dropped it; the step said BROKEN. It failed in the safe direction, but the report would have listed two caught errors as broken runs. Change: the summary line takes the sanitizer's report line. Lesson: the rule "evidence, else BROKEN" also needs a check that the evidence of each tool can reach the place where it is counted.

**IA-19. Vectors made by a writer do not test a reader on what the writer never writes.** The dictionary reader of the leaf was tested with 144 dictionaries made by the reference's own writer. The deliberate error "a value does not end at a carriage return" survived: the writer escapes that byte in values and never uses it as a line end, so no vector held one. The same hole would hide any difference in how the two readers treat input from a faulty or hostile controller. (The one place where it showed was an error in my own test, which put a raw byte 13 into a hand-made configuration.) Change: 54 more vectors, hand-made inputs (carriage returns as line ends, a line without "=", a key twice, empty values, a zero byte in the middle, a backslash at the end), each answered by the reference READER. The error is rejected now.

**IA-20. A helper with "changes nothing" as its whole contract stopped a termination proof.** `line_end()` (is this byte the end of a line?) had only `assigns \nothing`. The loop that walks the dictionary line by line must show that its position grows in every round; that follows from what `line_end()` answers, which the contract did not say. Two goals timed out (243 of 245). Change: the contract states the result exactly; the key comparison became a small function of its own with a loop over bytes, in place of a call that needed a cast between pointer types. General point, same as F-19 and F-23 of the proof report: a caller is proved from contracts only, so a contract must say everything that a caller's proof needs, also for a three-line helper.

**IA-21. State flags are separate bytes, so that a contract can speak about them.** The protocol layer kept its state marks ("HELLO sent", "waits for an answer", "peer was heard", "configuration in use") as bits of one byte. The code was right and the tests passed, but every statement about one mark became a statement about `flags & 0x04`, and the automatic provers are weak on mask reasoning (the classifier had shown that: F-4 of the proof report). Change: each mark is its own byte that holds 0 or 1. Cost: no RAM on the target (the bytes fit the padding; `struct ztl_leaf` is 7,136 bytes before and after, now pinned by a build-time assertion). Gain: "a frame goes out only to a peer that was heard" is a plain comparison in the contract. Lesson for the post: a data layout is a proof decision as well as a memory decision.

**IA-22. The gate's contract says where the delivered packet lies.** Before: the gate promised "the delivered body is the rest of exactly the packet that the primitive was asked about". That was enough while nothing read the result. The protocol layer reads the plain header in front of the body (the packet ID that an OK must repeat), 28 bytes before the pointer that the gate returns, and its proof could not show that this read is inside valid memory. Accepted wrong program, as far as the old contract went: a gate that returns a body with fewer than 28 readable bytes before it. Change: the contract states that the body is `dgram + 28` or the start of one reassembly slot plus 28, and that the 28 bytes before it are readable. Found by method (1): writing the real code behind an interface.

**IA-23. With no frame, the frame record says length 0.** Before: `ztl_input()` returned a bit set (reply, frame, configuration changed) and left the frame record untouched when no frame was delivered. A contract for that reads "if bit 1 of the result is set then ...", which is mask reasoning again, and a caller that forgets to test the bit reads the record of an earlier call. Change: the function writes length 0 and a null pointer first; the contract is "length at most 1,500; if not 0, the data are readable for that length". The statement needs no bit of the result, and the forgetful caller gets an empty frame.

**IA-24. The caller's proof found a statement that three functions did not make.** The theorem "each built packet takes exactly one packet ID, and a call that builds none takes none" was written on the three public functions. Their proofs failed at first: the functions that build the answers (OK to HELLO, OK to ECHO, OK to a frame) said nothing about the counter in their own contracts, and a caller is proved from contracts only. No code was wrong. But until each of those contracts said "moved by one if a packet was built, else unchanged", a version of them that takes two IDs, or none, would have been accepted function by function. Evidence after the change: the deliberate errors "packet ID not advanced" and "two IDs for one answer" are rejected by WP. The first complete run of the layer with contracts proved 1,751 of 1,759 goals; these were among the 8.

**IA-25. A true statement that one data model could not prove, removed by a change of the code.** One goal stayed open in the 32-bit model only: "the reply length is 0, or 28 to 2,048", on the path of a verb whose handler builds no reply. The handler cannot write the reply length. The prover had to conclude that from the handler's list of what it may change, through its model of memory, and it ran out of time. Change: the reply length is a local variable, written to the caller once at the one exit of the function. A local variable that no handler gets is unchanged without any reasoning. Same lesson as F-19: when the prover must show what a call leaves alone, change the code so that the question does not come up.

**IA-26. A deliberate error that no longer applies tests nothing.** The mutation step changes the sources by text patterns. After review fixes rewrote two lines, two patterns no longer matched. The runner reports that case ("NOT APPLIED") and fails the step, so the hole was guarded; but the runs between then and now had selected other errors by name, and the count "all rejected" silently stood for two errors that were in no run. Found by applying every pattern to the sources without a prover. Change: both patterns corrected (the protocol test rejects each), and the report claims "every error rejected" only from one run of the whole list.

**IA-27. A search for contracts that prove too much, and what it found.** A contract whose preconditions contradict each other proves every statement after it, so "all goals proved" alone cannot show that the contracts are sound. WP has a mode for this ("smoke tests"): for each function, each call and each statement it also tries to prove "false" at that place; a success means a contradiction or code that no input reaches. The runner had no such step until the whole leaf was under contract. First run, 1,000 such tests: no contradiction in any contract, and three reports, all at one place in the receive gate, a second test "an unencrypted packet must be HELLO" after the authentication call, kept as a defence in case the primitive changes the packet. WP proved that the test can never be true: the primitive's contract forbids the change. So the defence was code that no test could ever reach, and it would have stayed silent if it were wrong. Change: the branch is removed and an assertion states the fact at that place; the proof is now the defence. The step is part of every default run. Limit, for the post: a passed smoke test means that the provers found no contradiction in a short time, not that none exists; the tests that reach the code are the positive evidence.

## Known weak points, not yet changed

- ⚠️ The contract of `ztl_auth_open()` says what the function may change, not when it answers 1. A function that always answers 1 passes WP; only the test vectors reject it (mutant "the answer is always yes"). Closing this needs a specification of the tag inside the contract.
- ⚠️ Poly1305 as a whole (all blocks, the clamp of r, the padding of the last block) has no contract; the step contracts do not compose yet. Mutants in the loop are rejected by the vectors only. Planned route: a recurrence invariant, with the multipliers found by computer algebra (Grey's suggestion: `FindInstance` and relatives find the witness, the prover checks it).
- ⚠️ Salsa20/12 has no value contract in WP; its evidence is the vectors and a CBMC comparison with a model in the reference's form (running, no result yet).
- ⚠️ Constant time is by construction and by reading the compiled code, not by proof.
- ⚠️ The contracts of the protocol layer (`src/leaf.c`) state memory safety, bounds, the data invariant, authentication before effects and the packet ID rule. They do not state what a message means (the fields of a HELLO, when a configuration is refused, when a timer fires): the evidence for that is the loopback test against the reference node, the protocol test with sanitizers and the deliberate errors that only a test rejects. The LZ4 decoder and the dictionary reader have memory-safety contracts only: no contract says that the decoder's output is the LZ4 meaning of the block (58 vectors from the reference do).
- ⚠️ No protection against replay: a recorded authentic packet passes the gate again (Grey A9: after the measurements).
